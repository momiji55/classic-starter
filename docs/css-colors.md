
# CSS カラートークン ルール

classic-starter における、色の扱い方を定めたルールです。
このテーマを土台に新規案件を始める際は、本ルールに沿って色を組みます。

## 基本方針

| 項目 | 決定 |
|---|---|
| 定義場所 | `tokens.css` の `:root` に CSS 変数（`--color-*`）で定義 |
| 参照方法 | 各セレクタでは **必ず `var(--color-*)` で参照**する |
| 直書き | **生の HEX / `rgb()` をルール内に直接書かない** |

### なぜこの方針か

- **案件ごとの色替えが一箇所で済む** … `:root` の値だけ変えれば全ページに反映される。ボイラープレートとして再利用する前提に最適。
- **表記ゆれ・色の散乱を防ぐ** … 似た色が複数できてしまう事故を防ぎ、デザインの一貫性を保つ。
- **ダークモード等の拡張が容易** … `prefers-color-scheme` で `:root` の値を切り替えて対応している（[ダークモード](#ダークモード) を参照）。

## カラートークン

`:root` に以下の CSS 変数を定義し、色は必ずこの中から選ぶ。
（`tokens.css` の、スペーシングスケールと同じ `:root` 内で定義する）

```css
:root {
  /* カラー（テキスト）。文字色は「本文」と「補足」の2段階だけにし、主従の差をはっきりさせる */
  --color-text: #222;                /* 本文・見出し・強調テキスト */
  --color-text-inverse: #fff;        /* 暗背景の上に乗せるテキスト */
  --color-text-muted: #707070;       /* 補足テキスト（メタ情報・キャプション・引用・説明文）。白地でコントラスト比 4.5:1 以上 */
  --color-link: #1a73e8;             /* リンク */
  --color-required: #d93025;         /* 必須マーク・エラー */

  /* カラー（背景） */
  --color-bg: #fff;            /* 標準背景・カード */
  --color-bg-subtle: #f9fafb;  /* 薄い背景 */
  --color-bg-muted: #f3f4f6;   /* やや濃い薄背景（コード・テーブル・コメントの本文の箱） */
  --color-bg-inverse: #4a4a4a;      /* 暗い背景（ボタン・ホバーで反転した時）。白文字でコントラスト比 8.9:1 */
  --color-overlay: rgb(0 0 0 / 40%); /* パネルを開いた時の背面の暗幕 */

  /* カラー（ボーダー）。線は「構造を区切る薄い線（このトークン）」と「押せるものの濃い線（文字色 currentcolor）」の2種類だけにする */
  --color-border: #e5e7eb;        /* 構造の区切り線（ヘッダー・フッター・一覧・カード・引用の縦線） */
  --color-border-input: #8c8c8c;  /* 入力欄・select の枠。白地でコントラスト比 3:1 以上（WCAG 1.4.11） */
}
```

### 用途の目安

| 変数 | 主な用途 |
|---|---|
| `--color-text` | 本文、見出し、記事タイトル、コード・テーブルの文字 |
| `--color-text-inverse` | 暗背景の上に乗せるテキスト（白文字） |
| `--color-text-muted` | サイト説明文、メタ情報（日付等）、画像キャプション、引用の本文、補足テキスト、入力欄のプレースホルダー（読めるよう、専用の薄い色は作らない） |
| `--color-link` | リンク、リンクホバー時の色 |
| `--color-required` | フォームの必須マーク（`.required`）、エラー表示 |
| `--color-bg` | ページ背景、カード、入力欄、テーブルセル |
| `--color-bg-subtle` | コードブロック・テーブル見出し・コメントフォームの薄い背景。ヘッダーの上のサイト説明の帯とフッター（ページの上下を同じ色の面で挟む）、メニューの開閉ボタン |
| `--color-bg-muted` | インラインコード・テーブル・コメントの本文の箱のやや濃い薄背景 |
| `--color-bg-inverse` | ボタン（コメントの送信など）、ボタンのホバー時の暗い背景 |
| `--color-overlay` | パネル（ヘッダーの検索など）を開いた時に背面を覆う半透明の暗幕 |
| `--color-border` | ヘッダー・フッター・一覧・カード・テーブル・引用の縦線など、構造を区切る線（入力欄の枠は `--color-border-input`） |
| `--color-border-input` | 入力欄（コメント・パスワード・検索フォーム）と `select` の枠 |

### 文字色と線の色は2段階に絞る

- **文字色は「本文（`--color-text`）」と「補足（`--color-text-muted`）」の2段階だけ**にする。見出し用・引用用・キャプション用などの中間のグレーを増やさない（差が小さいグレーが並ぶと、情報の主従がぼやける）。見出しの強さは色ではなく、大きさと太さで付ける。
- **線は2種類だけ**にする。構造を区切る線は `--color-border`、押せるもの（ボタン・カテゴリ・タグ等）の枠は文字色（`currentcolor`）。ホバー・フォーカスで枠を強める時も、中間の色ではなく文字色（`--color-text`）にする。
- **例外は入力欄の枠**（コメント・パスワード・検索フォームの入力欄と送信ボタン、ウィジェットの `select`）。`--color-border` では白・薄い背景とのコントラストが約 1.2:1 しかなく、どこに入力するか分かりにくいので、専用の `--color-border-input`（約 3.4:1）にする（WCAG 1.4.11 の 3:1 以上）。補足の文字色（`--color-text-muted`。約 4.9:1）ほど濃くしないのは、入力欄が主役になりすぎないようにするため。**これ以上は薄くしない**（3:1 を下回ると基準を満たさない）。フォーカス時は文字色（`--color-text`）にし、あわせて輪郭線を枠に重ねて出す。

> 薄いグレー背景は名前から濃淡の順序が読み取れないため、**薄い順**をここに明記しておく。
> `--color-bg`（白）→ `--color-bg-subtle` → `--color-bg-muted`。

> `--color-bg` と `--color-text-inverse`（共に `#fff`）は
> **同じ値だが意味（役割）が異なる**ため別トークンにしている。
> 将来どちらか一方だけ調整したくなった時に分離しておくと安全。
> `--color-bg-inverse`（`#4a4a4a`）も元は `--color-text` と同じ `#222` だったが、
> ボタンの塗りが重く見えたため、文字色はそのままに背景だけ明るくしている（分けておいた効果が出た例）。
> `-inverse` は「通常と明暗が反転した面」を指す。案件でボタンなどを紺・えんじ等の
> ブランドカラーにしても名前が意味を失わないよう、見た目（dark/white）ではなく役割で命名している。

## 適用ルール

### 1. 色は必ず変数で参照する

```css
/* OK */
.post-item { background: var(--color-bg); border: 1px solid var(--color-border); }

/* NG: 生の HEX をルール内に直書きしない */
.post-item { background: #fff; border: 1px solid #e5e7eb; }
```

### 2. 役割に合ったトークンを選ぶ

同じ `#222` でも、文字色なら `--color-text`、暗い背景なら `--color-bg-inverse` を使う。
**見た目の色ではなく用途（役割）で選ぶ**こと。

### 3. 案件ごとの色替えは `:root` だけ編集する

ブランドカラーを変える際は各セレクタを触らず、`:root` のトークン値のみ変更する。
ただし、エディターのパレットに入れている色（下記）は、`functions.php` の色見本の HEX も同じ値に直す。

### 4. エディターで選べる色はトークンに絞る

ブロックエディターのパレットは `functions.php` の `editor-color-palette` で、次の役割のトークンだけにしている。カラーピッカー・グラデーション・WordPress 標準のパレットは無効にしている（本文に生の HEX が保存されないようにするため）。

| パレット（訳） | slug | トークン |
|---|---|---|
| Text（本文） | `text` | `--color-text` |
| Muted（補足） | `text-muted` | `--color-text-muted` |
| Background（背景） | `bg` | `--color-bg` |
| Subtle（薄い背景） | `bg-subtle` | `--color-bg-subtle` |
| Muted background（やや濃い背景） | `bg-muted` | `--color-bg-muted` |

- WordPress は `--wp--preset--color--{slug}` に登録した HEX を入れて出力するので、`tokens.css` の `body` でトークンに差し替えている（色見本以外はトークンから色が決まり、ダークモードでも追従する）。
- 色を足す時は `functions.php` のパレットと `tokens.css` の差し替えの両方に足す。リンク色・エラー色のように役割が決まっている色と、文字色と組で指定しないと読めない反転色（`-inverse`）は入れない。

## ダークモード

OS の配色設定（`prefers-color-scheme: dark`）に従って切り替える。サイト上の切り替えボタンは置かない。

### 仕組み

- `tokens.css` の `@media (prefers-color-scheme: dark)` で **`--color-*` の値だけを差し替える**。各セレクタ側には手を入れない。
- `:root` の `color-scheme: light dark` により、フォーム部品とスクロールバーもブラウザ側で切り替わる。
- `tokens.css` はブロックエディターでも読み込むので、エディターの本文も追従する。

### 差し替えないトークン

- `--color-text-inverse` … 暗幕（`--color-overlay`）の上に乗る文字にも使うため、ダークモードでも明るいままにする。
- `--color-border-input` … 暗い背景でもコントラスト比 3:1 を満たすので、そのまま使う。

### 維持するルール

色の手直しが出ないよう、以降も以下を守る。

1. **色はトークン経由だけで指定する。** CSS に加え、PHP で出力する HTML・インライン `style`・SVG の属性にも色を直書きしない。
2. **アイコンの色は `currentColor`** にして、文字色に追従させる。
3. **明るい背景を前提にした色の作り方をしない。** 色を薄く・濃く見せる目的で `opacity` や `mix-blend-mode`、黒・白の半透明の重ね合わせを使わない（フェードの表示切り替えに使う `opacity` は対象外）。半透明が必要な場合は `--color-overlay` のように `tokens.css` にトークンとして定義する。
4. **背景を持つ要素は背景色を明示する。** 下の面が透けると困る要素（ヘッダー、パネル、入力欄等）は `--color-bg` 系で塗る。境界線も `--color-border` 系のトークンで引く。
5. **新しいトークンは役割で命名する。** `light` / `dark` / `white` / `black` など、明暗を前提にした語を名前に入れない（ダークモードで値が逆になると名前が嘘になるため）。
6. **文字や線を画像で表現しない**（ロゴを除く）。画像は色を差し替えられない。

### 残っている検討事項

- 暗い背景で見えにくくなるロゴ・画像の扱い。案件ごとにロゴが変わるため、テーマ側では決めない。

## やってはいけないこと

- ルール内に生の HEX / `rgb()` / 色名を直接書く
- スケール外の似た色（例: `#e5e7ea` のような微妙に違う色）を新規追加する
- 用途と異なるトークンを流用する（背景色トークンを文字色に使う等）

## 関連

- トランジション・コンテナ幅・画面端の余白も同じ `:root` に `--transition-duration` / `--container-max` / `--gutter` として定義済み。色と同様に直書きせず変数を参照する。
- 角丸（`border-radius`）は使わない。角丸用のトークンも持たない。例外は形として円を描くもの（アバター）の `50%` だけ。
- ドロップシャドウ用のトークンは持たない。面の区切りは `--color-border` の 1px ボーダーで作り、そのまわりの余白は `docs/css-spacing.md` の「余白の段階」で取る。フォーカス中の入力欄も光彩は付けず、枠を文字色まで濃くしたうえで、`:focus-visible` の 2px の輪郭線を `outline-offset: -1px` で枠に重ねて出す。
- 余白のルールは [`css-spacing.md`](css-spacing.md) を参照。
